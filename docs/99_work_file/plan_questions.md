# Planフェーズ：質問事項と回答まとめ

## 1. 料金ページからのデータ取得について

### 質問内容
- WalkerPlusの料金ページのURL構造は？
- 料金情報はどのページから取得すべきか？
- 取得タイミングはバッチ処理時でよいか？

### 回答
- URL構造：`https://www.walkerplus.com/event/${eventId}/price.html`
- 取得タイミング：バッチ処理時でOK
- HTML構造：`<tr class="m-infotable__row"><th class="m-infotable__th">料金</th><td class="m-infotable__td">入場無料。</td></tr>`
- **料金情報の抽出方法**: テキストから数値を抽出する方が良い。無料の場合は数値が含まれないのでそれでOK

### 実装方針
- `HtmlFetcher`に`fetchPrice`メソッドを追加
- `extractFromPricePage`関数を作成して料金情報を抽出
- テキストから数値を抽出（正規表現を使用）
- `HtmlNormalizer`で`priceText`と`isFree`を設定

## 3. UI改善の具体的な方向性について

### 質問内容
- UI改善の具体的な方向性は？
- 既存のUIコンポーネントライブラリを使用するか、新規導入するか？

### 回答
- UI改善は任せる
- 新規導入してもOK
- リッチでエレガントなUIに
- 必要に応じて画像も使用可能

### 実装方針
- モダンなUIライブラリを検討（shadcn/ui、Radix UIなど）
- Tailwind CSSベースで改善
- カテゴリ選択をチェックボックス/マルチセレクトに変更

## 4. おすすめ理由と画像の表示位置について

### 質問内容
- 画像はイベントカードと詳細ページの両方に表示するか？
- おすすめ理由は詳細ページのみに表示するか？
- 画像がない場合のフォールバック画像は用意するか？

### 回答
- 画像は各サムネイルとして表示
- ホーム画面の週末おすすめにも表示
- イベント検索結果にも表示
- トップ画面でも画像を確認できるように
- おすすめ理由は詳細画面のみに表示
- **画像のフォールバック**: デフォルト画像を使用する

### 実装方針
- イベントカードに画像を追加
- 詳細ページに画像を追加
- 画像がない場合のフォールバック画像を用意（デフォルト画像）

## 6. 既存データの再分類について

### 質問内容
- 既存のDynamoDBデータを再分類する必要があるか？

### 回答
- 既存データも再分類する
- 既存の`weekly-ingest`バッチを実行すれば、データが変更される（洗い替えされる）
- 新しいバッチは作らない
- 既存のバッチを実行して、新しい料金情報も取得・設定できるようにする

### 実装方針
- 既存の`weekly-ingest`バッチに料金ページ取得機能を追加
- 既存の`weekly-ingest`バッチにカテゴリ再分類機能を追加
- 新しいバッチ処理は作らない
