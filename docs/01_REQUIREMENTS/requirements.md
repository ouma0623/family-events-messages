## 1. 背景（Background）
- 現状の課題：
  - フロントエンドの表示が不十分（おすすめ度が不要、画像が表示されない、おすすめ理由が表示されない、料金情報が表示されない）
  - イベント検索UIがざっくりしすぎている（キーワード検索のみ）
  - バックエンドで料金情報が取得されていない（料金ページから取得していない）
  - カテゴリ分類が不十分（大ジャンル・小ジャンルに分類されていない）
- 何が困っているか：
  - ユーザーがイベントを探しにくい
  - イベントの詳細情報が不足している
  - 検索機能が使いにくい
- なぜ今やるか（機会・リスク）：
  - ユーザー体験を向上させる必要がある
  - イベント情報を充実させる必要がある
  - 検索機能を改善する必要がある

---

## 2. 目的（Goal / Why）
- 達成したい状態：
  - フロントエンドで画像、おすすめ理由、料金情報が表示される
  - イベント検索UIがタグ選択式になり、大ジャンル・小ジャンルで分類できる
  - 無料・有料の選択ができる
  - バックエンドで料金ページから料金情報を取得し、数値を抽出できる
  - カテゴリがキーワードベースで自動分類され、大ジャンル・小ジャンルに分類される
  - 既存データも再分類される（`weekly-ingest`バッチ実行時に洗い替え）
- 成果の使われ方（誰が/いつ/何のために）：
  - ユーザー：イベントを探しやすくなり、詳細情報を確認できる
  - 開発者：バックエンドで料金情報を取得し、カテゴリ分類を改善できる

## 4. ユースケース / 利用シナリオ（Use Cases）
> 「誰が」「何を」「どうしたい」を簡潔に列挙する。

- UC-01：イベント一覧で画像を確認する
  - 利用者：ユーザー
  - 操作/入力：トップページまたはイベント検索ページでイベント一覧を表示する
  - 期待結果：各イベントカードに画像がサムネイルとして表示される

- UC-02：イベント詳細でおすすめ理由を確認する
  - 利用者：ユーザー
  - 操作/入力：イベント詳細ページを表示する
  - 期待結果：おすすめ理由が表示される

- UC-03：イベント詳細で料金情報を確認する
  - 利用者：ユーザー
  - 操作/入力：イベント詳細ページを表示する
  - 期待結果：料金情報が表示される（無料の場合は「無料」と表示、有料の場合は料金が表示される）

- UC-04：タグ選択でイベントを検索する
  - 利用者：ユーザー
  - 操作/入力：イベント検索ページで大ジャンル・小ジャンルを選択する
  - 期待結果：選択したタグに該当するイベントが表示される

- UC-05：無料・有料でイベントを絞り込む
  - 利用者：ユーザー
  - 操作/入力：イベント検索ページで「無料」「有料」を選択する
  - 期待結果：選択した条件に該当するイベントが表示される

- UC-06：バッチ処理で料金情報を取得する
  - 利用者：システム（バッチ処理）
  - 操作/入力：`weekly-ingest`バッチを実行する
  - 期待結果：各イベントの料金ページから料金情報を取得し、数値を抽出してDynamoDBに保存する

- UC-07：バッチ処理でカテゴリを自動分類する
  - 利用者：システム（バッチ処理）
  - 操作/入力：`weekly-ingest`バッチを実行する
  - 期待結果：各イベントのカテゴリがキーワードベースで自動分類され、大ジャンル・小ジャンルに分類される

## 5. 要件（Requirements）

### 5.1 機能要件（Functional）
> 実装対象となる要件。曖昧さを残さない。

- FR-01：おすすめ度の削除
  - 説明：フロントエンドからおすすめ度（`recommendScore`）の表示を削除する
  - 入力：`EventCard`コンポーネント、`events/page.tsx`（イベント詳細ページ）
  - 出力：おすすめ度が表示されないUI
  - 例外/異常系：なし
  - 受け入れ条件（Acceptance）：
    - イベントカードからおすすめ度が削除されている
    - イベント詳細ページからおすすめ度が削除されている

- FR-02：画像の表示
  - 説明：フロントエンドでイベント画像（`imageUrls`）をサムネイルとして表示する
  - 入力：`EventNormalized.imageUrls`（画像URLの配列）
  - 出力：イベントカードとイベント詳細ページに画像が表示されるUI
  - 例外/異常系：画像がない場合はデフォルト画像を表示する
  - 表示場所：
    - トップページの週末おすすめセクション
    - イベント検索結果のイベントカード
    - イベント詳細ページ
  - 受け入れ条件（Acceptance）：
    - イベントカードに画像がサムネイルとして表示される
    - イベント詳細ページに画像が表示される
    - 画像がない場合はデフォルト画像が表示される

- FR-03：おすすめ理由の表示
  - 説明：フロントエンドでイベントのおすすめ理由（`recommendReasons`）を表示する
  - 入力：`EventNormalized.recommendReasons`（おすすめ理由の配列）
  - 出力：イベント詳細ページにおすすめ理由が表示されるUI
  - 例外/異常系：おすすめ理由がない場合は表示しない
  - 表示場所：イベント詳細ページのみ
  - 受け入れ条件（Acceptance）：
    - イベント詳細ページにおすすめ理由が表示される
    - おすすめ理由がない場合は表示されない

- FR-04：料金情報の表示
  - 説明：フロントエンドでイベントの料金情報（`priceText`、`isFree`）を表示する
  - 入力：`EventNormalized.priceText`（料金テキスト）、`EventNormalized.isFree`（無料フラグ）
  - 出力：イベント詳細ページに料金情報が表示されるUI
  - 例外/異常系：料金情報がない場合は表示しない
  - 表示場所：イベント詳細ページ
  - 受け入れ条件（Acceptance）：
    - イベント詳細ページに料金情報が表示される
    - 無料の場合は「無料」と表示される
    - 有料の場合は料金が表示される
    - 料金情報がない場合は表示されない

- FR-05：料金ページからのデータ取得
  - 説明：バックエンドでWalkerPlusの料金ページ（`price.html`）から料金情報を取得する
  - 入力：イベントID（`eventId`）
  - 出力：料金情報（`priceText`、`isFree`）
  - 例外/異常系：料金ページが取得できない場合はエラーログを出力し、処理を続行する
  - 取得方法：
    - `HtmlFetcher.fetchPrice(eventId)`メソッドを追加
    - `extractFromPricePage(html)`関数を作成して料金情報を抽出
    - テキストから数値を抽出（正規表現を使用）
    - 無料の場合は数値が含まれないので`isFree = true`とする
  - 受け入れ条件（Acceptance）：
    - 料金ページから料金情報が取得できる
    - テキストから数値が抽出できる
    - 無料の場合は`isFree = true`が設定される
    - 有料の場合は`priceText`に料金情報が設定される

- FR-06：カテゴリのキーワードベース自動分類
  - 説明：バックエンドでカテゴリをキーワードベースで自動分類し、大ジャンル・小ジャンルに分類する
  - 入力：カテゴリ名（`categories`配列の各要素）
  - 出力：大ジャンル（`majorGenre`）、小ジャンル（`minorGenre`）
  - 例外/異常系：分類できない場合はデフォルト分類（「遊ぶ」）を適用する
  - 分類ルール：
    - **食べる**: 「食べ」「グルメ」「フード」「味覚」「狩り」「いちご」「フルーツ」「物産」「観光フェア」
    - **遊ぶ**: 「体験」「ワークショップ」「アクティビティ」「公園」「屋外」「スポーツ」「祭り」「フェア」「フェス」「パレード」「ライブ」「音楽」「子供」「恋人」「夫婦」「商業施設」
    - **見る・学ぶ**: 「展示」「企画展」「美術館」「文化施設」「科学館」「博物館」「図書館」「舞台」「演劇」「花」「自然」
  - 実装方法：
    - `packages/common/src/utils/categoryClassifier.ts`を作成
    - `classifyCategory(category: string)`関数を実装
    - `HtmlNormalizer`でカテゴリ分類を適用
  - 受け入れ条件（Acceptance）：
    - カテゴリがキーワードベースで自動分類される
    - 大ジャンル・小ジャンルが正しく分類される
    - 分類できない場合はデフォルト分類が適用される

- FR-07：既存データの再分類
  - 説明：既存のDynamoDBデータを再分類する（`weekly-ingest`バッチ実行時に洗い替え）
  - 入力：既存のDynamoDBデータ
  - 出力：再分類されたDynamoDBデータ
  - 例外/異常系：再分類エラーが発生した場合はエラーログを出力し、処理を続行する
  - 実装方法：
    - 既存の`weekly-ingest`バッチにカテゴリ再分類機能を追加
    - `clearExisting = true`の場合、既存データを削除してから新しいデータを取得・分類する
  - 受け入れ条件（Acceptance）：
    - 既存データが再分類される
    - 新しいデータも正しく分類される

- FR-08：タグ選択式検索UIの実装
  - 説明：フロントエンドでキーワード検索をタグ選択式に変更する
  - 入力：大ジャンル選択、小ジャンル選択、無料・有料選択
  - 出力：選択したタグに該当するイベントが表示されるUI
  - 例外/異常系：タグが選択されていない場合は全イベントを表示する
  - UI要件：
    - 大ジャンル（食べる・遊ぶ・見る学ぶ）を選択できる
    - 小ジャンル（既存カテゴリ）を選択できる
    - 無料・有料を選択できる
    - リッチでエレガントなUIにする
  - 実装方法：
    - `SearchForm`コンポーネントを修正
    - タグ選択UIを実装（チェックボックス/マルチセレクト）
    - 必要に応じてUIライブラリを導入（shadcn/ui、Radix UIなど）
  - 受け入れ条件（Acceptance）：
    - タグ選択式の検索UIが実装されている
    - 大ジャンル・小ジャンルで検索できる
    - 無料・有料で検索できる
    - UIがリッチでエレガントになっている

### 5.2 非機能要件（Non-Functional）
> 実務で崩れやすいので必ず書く。分からなければ仮置きして明示する。

#### 性能（Performance）
- 期待性能：既存の性能を維持する（UI改善による性能劣化は許容しない）
- 目標レスポンス：既存のAPIレスポンス時間を維持（2秒以内）
- 許容バッチ時間：既存のバッチ処理時間を維持（weekly-ingest: 15分以内）
- 画像読み込み時間：画像の読み込み時間は3秒以内

#### 可用性（Availability）
- 目標稼働：既存の稼働率を維持する（UI改善によるダウンタイムは許容しない）
- 障害時の許容：UI改善中に既存システムが停止しないこと
- 復旧時間：UI改善エラーが発生した場合、30分以内にロールバックできること

#### セキュリティ（Security）
- 認証/認可：既存の認証・認可機構を維持する（Cognito UserPool、API Gateway JWT認証）
- 取り扱う機密情報：既存のシークレット管理を維持する（Secrets Manager）
- ログに残してよい/悪い情報：既存のログ出力方針を維持する（機密情報はログに出力しない）

#### 運用（Operations）
- 監視/アラート（必要なら）：既存の監視・アラート設定を維持する（CloudWatch Logs、SNSトピック）
- ロールバック方針：UI改善エラーが発生した場合、前回のUI状態に戻すことができること
- 運用手順の格納先：`docs/03_OPERATIONS/runbook.md`
- エラー時の対応：ログ確認→原因特定→修正の順で対応する

#### 監査/証跡（Audit）
- Issueに残すべき証跡：UI改善・バックエンド改善の実施内容、検証結果、問題発生時の対応
- Notionに残すべきまとめ：UI改善手順、バックエンド改善手順、動作確認結果、問題発生時の対応手順
